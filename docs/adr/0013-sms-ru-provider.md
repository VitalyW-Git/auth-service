# 0013. SMS.ru — провайдер SMS, тестовый режим только в разработке

- **Статус:** принято
- **Дата:** 2026-10-18

## Контекст

Вход по телефону ([ADR 0011](0011-phone-signup-funnel.md)) отправляет код из SMS. До сих пор `LogSmsSender` писал
текст SMS в лог сервера. Нужен настоящий провайдер с российскими номерами и способ проверять интеграцию,
не тратя баланс.

## Решение

- **Провайдер — SMS.ru**, метод `POST https://sms.ru/sms/send` с `json=1`, реализация `SmsRuSmsSender`.
- **Выбор отправителя** — фабрика `createSmsSender`: задан `SMS_RU_API_ID` → SMS.ru, иначе `LogSmsSender`
  (только в разработке).
- **Тестовый режим** — параметр SMS.ru `test=1`: запрос проверяется, ответ как при отправке, но SMS не уходит и баланс
  не списывается. В разработке включён по умолчанию (`SMS_RU_TEST_MODE`), текст SMS пишется в лог.
  При `NODE_ENV≠development` и `SMS_RU_TEST_MODE=true` сервер не стартует: коды не дошли бы до пользователей.
- **Локальная заглушка вместо SMS.ru** — `SMS_RU_API_URL` подменяет базовый адрес API на `tools/sms-ru-mock.mjs`,
  который отвечает в формате SMS.ru и печатает текст SMS. Нужна потому, что без согласованного буквенного
  отправителя аккаунт SMS.ru отвечает ошибкой 221 на любой запрос, включая `test=1` и даже `sms/cost`, — успешная
  ветка `SmsRuSmsSender` иначе не проверяется. Непустое значение вне `development` — ошибка при старте.
- **Клиент знает о тестовом режиме**: `POST /auth/phone/code` отвечает `{ isTestMode }`, страница входа подсказывает,
  что код — в логе сервера.
- **Ошибки SMS.ru** переводятся в ответы: неверный номер или нет маршрута (202, 207, 214) → 400, лимиты на номер
  (230–233) → 429, остальное и недоступность → 503. Неотправленный код удаляется, чтобы не блокировать повтор на 60 с.

## Последствия

- Для реальной отправки нужны `api_id` из личного кабинета SMS.ru, пополненный баланс и, при желании, согласованное
  имя отправителя (`SMS_RU_SENDER`).
- В лог попадают коды SMS.ru, но не текст SMS вне тестового режима.
- Параметр `ip` (лимиты SMS.ru по IP пользователя) пока не передаётся: локально адрес из частной сети, SMS.ru
  отвечает на него ошибкой 507. Подключить вместе с лимитом по IP на нашей стороне.

## Отвергнутые варианты

- **Twilio.** На российские номера практически не доставляет.
- **Мок API в Docker (WireMock).** Проверяет только наш код, а не настоящий ответ провайдера. Тестовый режим SMS.ru
  бесплатен и проверяет то и другое. Заглушка всё же понадобилась (`SMS_RU_API_URL`), но как обход блокировки 221,
  а не замена тестовому режиму: отдельный контейнер для этого избыточен, хватает скрипта на `node:http` без
  зависимостей.
- **Отдавать код в ответе API в разработке.** Легко забыть выключить, а лог сервера и так под рукой.
