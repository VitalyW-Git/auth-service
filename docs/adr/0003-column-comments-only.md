# 0003. Комментарии в БД — только к колонкам

- **Статус:** принято
- **Дата:** 2026-10-11

## Контекст

Схему читают не только из кода, но и в psql, DBeaver и других инструментах. Нужно единое место, где
описан смысл каждой колонки.

## Решение

- У каждой новой колонки — `comment on column`, на английском, одна короткая фраза о содержимом:
  для `clinics.name` — `'Display name shown to staff and patients'`.
- К таблицам комментарий не пишется: назначение видно из имени и колонок, а комментарий таблицы дублирует их
  и устаревает первым.
- В комментарий не пишутся архитектурные пояснения («продублировано ради индекса») — для этого есть ADR.
- Тот же текст — в `comment` декоратора сущности, иначе `migration:check` увидит расхождение.
- Комментарии к уже существующим колонкам добавляются только отдельной задачей.

## Последствия

Справочник по колонкам генерируется из базы (`docs/schema/`), руками колонки нигде не описываются.

## Отвергнутые варианты

- **Комментарии и к таблицам.** Дублируют имя таблицы, первыми устаревают.
- **Русский язык в комментариях БД.** Комментарии — часть схемы, их читают внешние инструменты; общий язык
  схемы — английский (исключение из правила «комментарии в коде — по-русски»).
