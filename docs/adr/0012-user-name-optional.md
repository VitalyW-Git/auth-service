# 0012. `users.name` вместо `display_name`, имя необязательно

- **Статус:** принято
- **Дата:** 2026-10-14

## Контекст

Вход по телефону ([ADR 0011](0011-phone-signup-funnel.md)) создаёт аккаунт для нового номера сразу после
кода из SMS. Имени на этом шаге нет, а `users.display_name` был обязательным. Колонка досталась от Prisma
(ограничение `users_displayName_not_null`), и её название расходится с `RegisterDto.name`.

## Решение

- Колонка переименована в `users.name` и стала nullable (миграция `RenameDisplayNameToName`).
- В API поле называется `name` вместо `displayName`.
- Регистрация по email по-прежнему требует имя: поле есть на форме, `RegisterDto.name` обязателен.
- Как получать имя у аккаунтов без него, решится вместе с записью на приём.

## Последствия

- Код, который показывает имя пользователя (кабинет, карточки, письма), должен учитывать `NULL`.
- Ответы `/auth/login`, `/users/profile` и другие отдают `name` вместо `displayName`, фронтенд обновлён вместе с ними.

## Отвергнутые варианты

- **Заглушка вместо имени** (замаскированный номер или часть email). Она попала бы в карточки пациентов
  и расписание клиники как настоящее имя.
- **Спрашивать имя сразу после кода** (экран «Почти готово»). Лишний шаг во входе. Отложено до записи на приём,
  где имя действительно нужно.
