# 0005. `check`-ограничения — только для логики

- **Статус:** принято
- **Дата:** 2026-10-11

## Контекст

В первой версии схемы расписания были `check` и на формат данных: непустые имена
(`char_length(btrim(name)) > 0` у клиник, врачей, услуг, пациентов) и формат телефона E.164 у пациентов.

## Решение

`check` в базе оставляются только там, где нарушение ломает логику системы:

| Ограничение                                                      | Что защищает                                                        |
|------------------------------------------------------------------|---------------------------------------------------------------------|
| `appointments_time_range_check`                                  | конец записи позже начала                                           |
| `appointments_cancellation_check`                                | у отменённой записи есть время и автор отмены, у неотменённой — нет |
| `clinic_services_duration_minutes_check`                         | длительность услуги больше нуля                                     |
| `doctor_working_hours_weekday_check`, `..._time_range_check`     | день недели 1–7, конец интервала позже начала                       |
| `doctor_schedule_exceptions_date_range_check`, `..._hours_check` | корректный диапазон дат; часы заданы ровно для `CUSTOM_HOURS`       |
| `users_phone_verified_check`                                     | подтверждения телефона без телефона не бывает                       |

Проверки формата (непустые строки, формат телефона) — в приложении: DTO (class-validator) и value objects.

## Последствия

- **Телефон приводится к E.164 только в приложении** — value object `Phone` нормализует номер при создании.
  Без этого `8 916…` и `+7 916…` станут разными пациентами, и уникальность `(clinic_id, phone)` перестанет работать.
- Пустые имена отсекает валидация DTO; в базе защиты от них нет.

## Отвергнутые варианты

- **`check` на всё, что можно выразить.** Дублирует валидацию приложения, а ошибки формата не портят данные
  необратимо и легко исправляются.
