# 0002. Выравнивание таблиц users / accounts / tokens

- **Статус:** принято
- **Дата:** 2026-10-11
- **Миграция:** `Migration20261011150640_AlignLegacySchema`

## Контекст

При сверке сущностей с живой базой выяснилось, что таблицы `users`, `accounts`, `tokens` созданы не
миграциями MikroORM (судя по типам и именам — Prisma), хотя первая миграция MikroORM отмечена как
выполненная. Фактическая схема расходилась с сущностями:

|                          | Сущности и миграции                              | База                                                         |
|--------------------------|--------------------------------------------------|--------------------------------------------------------------|
| `id`, `user_id`          | `uuid`                                           | `text`                                                       |
| время                    | `timestamptz`                                    | `timestamp(3)` без часового пояса                            |
| `role`, `method`, `type` | `text` + `check`                                 | нативные типы `"UserRole"`, `"AuthMethod"`, `"TokenType"`    |
| уникальность, FK         | `users_email_unique`, `accounts_user_id_foreign` | уникальный индекс `users_email_key`, `accounts_user_id_fkey` |

Последствия расхождения: внешний ключ `uuid` на `users.id` типа `text` невозможен, а `migration:check`
никогда не показал бы «нет изменений».

## Решение

Отдельная миграция приводит базу к схеме сущностей: `text` → `uuid` (все значения были корректными uuid),
`timestamp(3)` → `timestamptz`, нативные enum-типы → `text` + `check` с последующим удалением типов,
уникальные индексы → ограничения через `unique using index`, внешний ключ с именем MikroORM и индексом
`accounts_user_id_index`, у `created_at` — `default now()`.

**Время переведено как `Europe/Moscow`, а не UTC.** Приложение работает в `Europe/Moscow`, драйвер `pg`
передаёт дату со смещением `+03:00`, а колонка без часового пояса это смещение отбрасывала — в базе лежало
московское время.

Строковые колонки остались `text`; под базу поправлены сущности (`type: 'text'`), а не наоборот.

## Последствия

- `down()` полностью возвращает схему Prisma.
- Сущности `UserEntity`, `AccountEntity`, `TokenEntity` выровнены под базу.
- Комментарии к старым колонкам не добавлялись — это отдельная задача.

## Отвергнутые варианты

- **Ссылаться на `users.id` как `text`.** Расхождение сущностей с базой осталось бы навсегда.
- **Пересоздать базу (`migration:fresh`).** Удаляет данные пользователей.
- **Привести строки к `varchar(255)` из сущностей.** 255 — случайный лимит, OAuth-токен в него может не влезть.
