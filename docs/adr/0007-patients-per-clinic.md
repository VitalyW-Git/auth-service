# 0007. Пациенты: карточка в каждой клинике, аккаунт и подтверждённый телефон

- **Статус:** принято; вход пациента и хранение SMS-кодов — заменено [0011](0011-phone-signup-funnel.md)
- **Дата:** 2026-10-11

## Контекст

Пациент записывается в клинику, при этом может лечиться в нескольких клиниках и видеть все свои записи
(«Мои записи» на макете). Данные пациента принадлежат клинике (152-ФЗ: оператор персональных данных —
клиника). Онлайн-запись должна быть доступна только пациентам с подтверждённым телефоном.

## Решение

- **`patients` — карточка пациента в конкретной клинике**, уникальность `(clinic_id, phone)`. У одного человека
  своя карточка в каждой клинике.
- **`patients.user_id`** (nullable, `on delete set null`) — связь с учётной записью, уникальность
  `(clinic_id, user_id)`. `NULL` — карточку создал сотрудник для пациента без аккаунта.
- **Вход пациента — по email и паролю**, как у сотрудников; затем пациент добавляет и подтверждает телефон.
- **`users.phone`** (`varchar(16)`, nullable, уникальный) и **`users.phone_verified_at`** (`timestamptz`) —
  телефон учётной записи и время подтверждения кодом из SMS. Подтверждение действует во всех клиниках.
  `users_phone_verified_check`: подтверждения без телефона не бывает.
- **Правило записи:** онлайн-запись (источники `WIDGET`, `WEBSITE`) — только при `phone_verified_at is not null`;
  сотрудник клиники (`PHONE`, `ADMIN`) может записать любого пациента. Просмотр своих записей доступен всегда.
  Правило проверяет домен: условие касается другой таблицы, `check` его не выразит.

## Последствия

- «Мои записи» ищутся по `patients.user_id` (индекс `patients_user_id_index`) во всех клиниках.
- При смене телефона `phone_verified_at` сбрасывается в `NULL`.
- Хранение SMS-кодов — задача раздела «Запись пациента» (вероятно, `tokens` с новым типом; у `tokens`
  обязательная колонка `email` — понадобится миграция).

## Отвергнутые варианты

- **Общий реестр пациентов на всю платформу.** Раскрывал бы одной клинике данные из другой.
- **Пациент без учётной записи, только телефон + SMS при каждой записи.** Заменено требованием аккаунта
  с подтверждённым телефоном.
- **Вход пациента по телефону и коду из SMS.** Потребовал бы сделать `users.email` и `password` необязательными
  и менять модуль `auth`; отложено.
