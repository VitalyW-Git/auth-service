# Документация проекта

Документация живёт рядом с кодом и меняется **в том же коммите**, что и код, который она описывает.
Если меняется схема, правило предметной области или процесс — в том же коммите правится и документ.

## Что где лежит

| Каталог | На какой вопрос отвечает | Как ведётся |
|---|---|---|
| [`adr/`](adr/) | **Почему** сделано так, а не иначе | Один файл на одно решение, руками. Принятый ADR не переписывается — его отменяет или уточняет новый |
| [`domain/`](domain/) | Что значат понятия, какие правила действуют, где они обеспечиваются | Файл на ограниченный контекст (`src/modules/<context>`), руками |
| [`processes/`](processes/) | Как проходит бизнес-процесс по шагам и какие команды/запросы его выполняют | Файл на процесс, руками |
| [`schema/`](schema/) | Какие таблицы, колонки и связи есть в базе | **Генерируется** из живой БД, руками не править |

Описание колонок в одном месте — в комментариях БД (`comment on column`, на английском). В `domain/` колонки
не перечисляются: там смысл понятий и правила, а справочник по колонкам — в `schema/`.

## ADR

| № | Решение |
|---|---|
| [0001](adr/0001-migration-first.md) | Сначала миграция, потом сущности; снимок схемы MikroORM отключён |
| [0002](adr/0002-legacy-schema-alignment.md) | Выравнивание таблиц users / accounts / tokens, созданных не миграциями MikroORM |
| [0003](adr/0003-column-comments-only.md) | Комментарии в БД — только к колонкам, на английском |
| [0004](adr/0004-enums-as-text-check.md) | Перечисления в БД — `text` + `check`, не нативный enum |
| [0005](adr/0005-db-checks-for-logic-only.md) | `check`-ограничения — только для логики, проверки формата — в приложении |
| [0006](adr/0006-platform-and-clinic-roles.md) | Роль на платформе (`users.role`) и роль в клинике (`clinic_members`) — разные уровни |
| [0007](adr/0007-patients-per-clinic.md) | Карточка пациента — отдельно в каждой клинике; связь с аккаунтом и подтверждение телефона |
| [0008](adr/0008-appointment-time-model.md) | Модель времени записи: `starts_at`/`ends_at`, часовой пояс клиники, защита от пересечений |
| [0009](adr/0009-clinic-slug-deferred.md) | `clinics.slug` отложен до публичной страницы записи |
| [0010](adr/0010-clinic-services-naming.md) | Таблица услуг называется `clinic_services` |
| [0011](adr/0011-phone-signup-funnel.md) | Воронка записи по телефону: аккаунт создаётся кодом из SMS |
| [0012](adr/0012-user-name-optional.md) | `users.name` вместо `display_name`, имя необязательно |
| [0013](adr/0013-sms-ru-provider.md) | SMS.ru — провайдер SMS, тестовый режим только в разработке |

Новый ADR: следующий номер, имя `NNNN-kebab-case.md`, структура — как в [`adr/template.md`](adr/template.md).

## Предметная область и процессы

- [`domain/clinic.md`](domain/clinic.md) — клиники, сотрудники, врачи, услуги, график работы.
- [`domain/appointment.md`](domain/appointment.md) — пациенты и записи на приём.
- [`processes/booking.md`](processes/booking.md) — запись на приём: онлайн пациентом и сотрудником клиники.
- [`processes/phone-login.md`](processes/phone-login.md) — вход по коду из SMS, создание аккаунта по номеру.
